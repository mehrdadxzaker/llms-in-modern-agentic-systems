A reader's guide to the survey

From fluent output to dependable action

The central transition in agentic systems is not from one model to another. It is from producing a response to acting in a closed loop with evidence, constraints, and feedback.

The reader question

What changes when a model can act?
It gains capability only through a larger system; that same system must make its authority observable and controllable.

An LLM can write a plausible answer. A dependable system must also know what it knows, what it may do, how it will check itself, and when it must stop.

Act I • The boundary

Not every LLM system is an agent

The paper starts by separating increasingly adaptive system forms. This matters because each form delegates a different amount of control to the model.

LLM application

The model answers, summarizes, classifies, or extracts. Control remains outside the model.

RAG application

The model synthesizes over retrieved evidence, but the retrieve-and-generate sequence is mainly predetermined.

LLM workflow

A developer-authored graph may include state and tools, while most branching remains explicit and inspectable.

Bounded agent

The model can select permitted next actions from observations, under budgets, stopping rules, and authorization boundaries.

Multi-agent system

Several bounded agents coordinate tasks, evidence, or control, creating both new capability and new accountability boundaries.

Act II • The loop

RAG becomes agentic when retrieval is a decision

Retrieval is not replaced by an agent. It becomes one capability among planning, memory, computation, communication, and action.

1. Gather

Start from a user goal, retrieve scoped evidence, and preserve provenance rather than treating the model as the source of truth.

2. Interpret

Rank, filter, and synthesize evidence. A plausible answer is still only a hypothesis until its support is checked.

3. Return or revise

If support is incomplete or conflicting, retrieve again, re-plan, abstain, or escalate instead of confidently continuing.

Act III • The architecture

Agency lives in the system around the model

The model may propose an action, but the runtime decides whether that action has a valid schema, authority, budget, and verifiable consequence.

STATE

Remember selectively

Separate task state, evidence, generated notes, and stable preferences. Every persistent memory needs scope and provenance.

POLICY

Choose under constraints

Plans are hypotheses. New observations, permissions, and tool results can invalidate a proposed next step.

ACTION

Commit through contracts

Typed tools, least privilege, budgets, and validation make an action interface safer than unstructured text.

TRACE

Make behavior inspectable

Record sources, decisions, tool calls, outcomes, approvals, costs, and side effects so failures can be understood.

Act IV • The evidence

Success is more than the final answer

Agent evaluation must ask whether a system reached the right state, took a safe trajectory, recovered from failure, and justified its cost and authority.

Outcome

Did the requested record exist, test pass, form submit, or task state change as intended?

Trajectory

Did the system make valid tool calls, avoid loops, recover from interruptions, and preserve policy boundaries?

Deployment

What did it cost, what side effects occurred, and did people retain meaningful oversight at consequential decisions?

Act V • The decision

Autonomy should be earned

The appropriate architecture depends on uncertainty, the cost of error, available verification, and whether external action can be made reversible.

Need evidence?

Use retrieval with provenance and access control.

Known process?

Use a workflow with explicit branches, retries, and approval gates.

Uncertain next step?

Use a bounded agent only where it can observe, act through contracts, and verify progress.

Distinct roles?

Use multiple agents only when their tools, evidence, or verification responsibilities are genuinely complementary.

The conclusion

Build bounded, evidence-aware, verifiable autonomy.

The credible path is disciplined composition: evidence with provenance, actions with contracts, memory with governance, learning with regression controls, and evaluation that measures outcomes, cost, and risk together.
